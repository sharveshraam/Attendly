# Attendly website — architecture

_Last updated: 2026-11-03 (website refresh on branch `arena/6fedf57b-attendly`)._

## System context

Attendly has one live Supabase backend (`Attendly`, ref `gavlxbxgxdormbfhtzlo`,
`ap-south-1`) already used by the deployed Android app. This repository now
contains the **website** — a Next.js App Router application at the repository
root. The two clients share the same Auth users, Postgres tables, RLS policies,
Storage bucket and Realtime publication. There is no second database, no second
attendance engine and no web-only API layer.

```
Browser (website PWA)                Android app (unchanged)
        │                                    │
        └──────────── Supabase JS/SSR ──────┘
                 publishable key + RLS
                         │
        Auth · Postgres (19 RLS tables) · Realtime (6 tables)
        Storage: academic-documents (private)
```

No migrations, schema changes, RLS policy edits, Edge Functions or Storage
policy changes were made for the website. The only Auth change is the approved
additive redirect allow-list; `site_url` and all other Auth settings are
unchanged. **Obsidian Academic** is a CSS/token-level, dark-first design system
in `app/web.css` with a locally bundled Inter font — no backend, mobile or
infrastructure change.

## Layers

| Layer | Location | Responsibility |
| --- | --- | --- |
| Routing / SSR guard | `app/`, `proxy.ts`, `app/(app)/layout.tsx` | Public pages, auth pages, protected app routes, session-cookie refresh. |
| Presentation | `components/`, `app/web.css` | Reusable UI primitives, charts, forms, shell, providers, public/auth pages. |
| Domain logic | `lib/attendance/engine.ts`, `lib/schedule.ts`, `lib/import/csv.ts`, `lib/dates.ts`, `lib/assistant.ts`, `lib/reports.ts` | Pure, testable calculations; no React, no network. |
| Validation | `lib/validation.ts` | Zod schemas for every write and for file uploads. |
| Data access | `lib/data.ts` | Single gateway to the live schema using the browser publishable client. All authorization delegated to existing RLS. |
| Auth flows | `lib/auth.ts`, `app/auth/callback/page.tsx` | Email/password signup + confirmation, sign-in, recovery/reset, resend confirmation, sign-out, PKCE/token-hash/implicit redirect handling. |
| State | `hooks/use-workspace.tsx` | One RLS-filtered snapshot per signed-in user, derived canonical stats, pending offline overlay, realtime invalidation, sync/conflict actions. |
| Offline | `lib/offline.ts`, `public/sw.js`, `public/offline.html`, `components/pwa.tsx` | Deterministic outbox, optimistic-concurrency sync, per-user private cache, static-shell-only service worker, install/update/offline UI. |

## Routes

- Public: `/`, `/features`, `/about`, `/privacy`, `/terms`, `/support`.
- Auth: `/login`, `/signup`, `/forgot-password`, `/reset-password`, `/verify-email`, `/auth/callback`.
- Authenticated (all under the `(app)` route group, guarded twice — `proxy.ts` and the server layout): `/onboarding`, `/home`, `/calendar`, `/courses`, `/courses/[id]`, `/attendance`, `/groups`, `/groups/[id]`, `/productivity`, `/analytics`, `/assistant`, `/notifications`, `/settings`.
- PWA: `/manifest.webmanifest` (generated by `app/manifest.ts`), `/sw.js`, `/offline.html`, `/offline`, `/icons/*`.

`app/(app)/layout.tsx` is a server component that validates the session with
`getUser()` and shows an explicit setup state if Supabase is not configured.
`proxy.ts` refreshes the SSR cookie and redirects unauthenticated app-route
requests to `/login`. Neither replaces RLS.

## Attendance semantics

`lib/attendance/engine.ts` is the canonical, pure engine, ported from the mobile
app and covered by tests. `lib/attendance-engine.js` is a compatibility adapter
for the original six legacy tests. Key rules:

- denominator = `present + absent`; `excused` sessions are conducted but excluded;
- `unmarked` is never counted and never auto-absent;
- `cancelled` and `rescheduled` originals are excluded; a replacement counts once;
- extra classes are ordinary dated sessions;
- class-count bunk/recovery uses epsilon-safe floor/ceil; hours mode uses
  duration and `attended_minutes ?? scheduledMinutes`;
- 100% targets are unrecoverable after a miss; percentages round to one decimal;
- projections are deterministic and `futureUnits` is `null` when the future
  schedule is unknown.

No component recalculates attendance independently.

## Schedule generation

`lib/schedule.ts` expands `timetable_rules` (weekday `0=Sun..6=Sat`) inside the
semester window, honours `academic_days` classifications and rule validity dates,
and deduplicates by `courseId|startsAt`. `lib/import/csv.ts` parses RFC-4180 CSV
client-side; `components/timetable-import.tsx` requires human review before any
write. PDF/image/Excel files are stored privately for provenance only — the live
project has **no OCR or AI extraction service** (zero Edge Functions), so no rows
are invented from them.

## Groups and privacy

Group pages query `calendar_events` (shared schedule), `calendar_polls`,
`calendar_poll_votes`, `group_members`, `schedule_change_log` and the group-linked
`semesters`. They never query `attendance_records`, personal analytics or bunk
calculations. `profiles` are self-select only; other members' attendance is not
readable under RLS. `tests/privacy.test.ts` enforces this structurally.

## Offline model

- The service worker caches **only** `/offline.html`, the manifest, the icon and
  `/_next/static/` / `/icons/` assets. It refuses to cache navigations, `/api/`,
  `/auth/`, requests with `Authorization`/`Cookie` headers, auth `code` /
  `token_hash` URLs and cross-origin requests. No private API response or token
  is ever stored by the SW.
- Private data is cached in `localStorage` under per-user keys and can be
  disabled/cleared in Settings; it is cleared on sign-out.
- Every queued attendance mark has a deterministic id `attendance:<eventId>`,
  a `baseRecordId` + `baseMarkedAt` version, and one pending edit per event.
  `syncOutbox()` refuses to overwrite a newer server value; conflicts require an
  explicit keep-local/discard-local choice before a single idempotent upsert.

## Build and runtime

Next.js 16.4.4 (App Router, Turbopack), React 19.2.0, TypeScript 5.9.3,
Tailwind 4.3.4 via `@tailwindcss/postcss`, `@supabase/ssr` 0.12.7,
`@supabase/supabase-js` 2.116.0, `zod` 4.6.7, `lucide-react`. Only public
`NEXT_PUBLIC_SUPABASE_URL` and `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` (or the
legacy anon key) are read. `next.config.ts` sets conservative security headers
and a CSP whose `connect-src` allows only self and `*.supabase.co`.
