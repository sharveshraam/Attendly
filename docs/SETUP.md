# Local setup

## Prerequisites

- Node.js **22+** (verified on 22.22.3) and npm 10+.
- Access to the existing live Supabase project `Attendly`
  (ref `gavlxbxgxdormbfhtzlo`, `ap-south-1`). **Do not create a second project,
  re-run the migration or change Auth/RLS/Storage settings.**
- A copy of `.env.example` → `.env.local` with the project's **public** URL and
  publishable key. These are browser-safe values; authorisation is RLS.

```bash
cd /home/user/Attendly
npm install
cp .env.example .env.local
# edit .env.local with the real public values
npm run dev
```

Open `http://localhost:3000`. `npm run dev` binds `0.0.0.0` so it also works in
the Arena live preview.

## Environment variables

| Variable | Required | Notes |
| --- | --- | --- |
| `NEXT_PUBLIC_SUPABASE_URL` | yes | `https://<project-ref>.supabase.co` |
| `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` | yes (or legacy anon) | `sb_publishable_…` from Supabase API keys |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | legacy fallback | Only if the project still uses an anon JWT |

Never set a service-role/secret key, database password or AI provider key. The
website does not read them and a static privacy test fails if one appears in
browser code.

If env vars are missing, public pages still render and authenticated routes show
an explicit "Supabase is not configured for this deployment" state instead of
fake data.

## Auth on localhost

The live Auth config already allows `http://localhost:3000/**` with
`site_url=http://localhost:3000`, so signup confirmation and recovery links work
locally. External providers are disabled — use email/password only.

Do **not** test with real production user data. Use a disposable test account and
a safe test environment; see `docs/TESTING.md`.

## PWA notes

- `app/manifest.ts` generates `/manifest.webmanifest`; there is no duplicate
  static manifest.
- `public/sw.js` is registered by `components/pwa.tsx`. It caches static shell
  assets only and is served with `Cache-Control: no-store`.
- Icons are generated by `scripts/generate-icons.py` (pure Python, no Pillow
  dependency) into `public/icons/`.
- To test install/offline behaviour, use the production build (`npm run build &&
  npm run start`) in a Chromium browser; dev mode does not register the SW the
  same way.
